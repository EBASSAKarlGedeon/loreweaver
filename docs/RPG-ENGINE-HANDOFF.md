## 1. What this project is

Loreweaver (SillyTavern fork, AGPL, repo `C:\Users\Gedeon\Documents\Coding\Loreweaver`, branch `release`) + the **RPG Engine port**: the MNO Perchance RPG generator running as a Loreweaver extension, with AI calls routed through Loreweaver's backend.

**Agreed architecture (do not revisit):**
- Do NOT merge the two frontends. RPG Engine keeps its own game UI; Loreweaver owns providers/keys/presets/characters/World-Info/storage/sync.
- One app, two workspaces. Integration happens through a **server-side bridge**, never through `SillyTavern.getContext()` or iframe parent access.
- Presets/connections = **live references**; characters/World-Info/lorebooks = **linked snapshots** with source id + explicit re-import (never auto-overwrite a running adventure).
- `narrator-prompt.md` stays the GM base contract; Loreweaver prompt content may only be added as an explicit optional "additional GM instructions" section.
- Keep `app/src/` untouched where possible (port stays upgradable); any required patch goes into a `PATCHES.md` in the port with file/line notes.

## 9. Lessons learned (Problem → Cause → Solution — add new ones here)

- **Overlay pages invisible (buttons "do nothing", found via user recording, 2026-11-18).** *Problem:* "Open Loreweaver bridge" and "Import from Loreweaver" opened no overlay; the game button worked. *Cause:* overlay CSS still scoped to old ids (`#rpge-bridge-root`) while the generalized JS created new ids (`rpge-page-*`) → zero styles, invisible. *Solution:* scope overlay styles by CLASS (`.rpge-page-root`/`.rpge-page-frame`, `0993ab6`); after ANY root-extension `index.js`/`style.css` change run the visual check `node tools/shot-overlays.js` (clicks both buttons + screenshots) — the root extension has NO automated test (the fake-ST harness only exercises the port wrapper), so such regressions are otherwise invisible until the user hits them. FAQ entry added.
- **Nested-extension CSS never loads.** *Problem:* game overlay unstyled. *Cause:* ST/Loreweaver only auto-loads the manifest CSS of top-level extension folders; the port is nested. *Solution:* the port wrapper injects its own `<link>` (`ensureStyles`). Same rule for any nested page.
- **Fixed overlays collapse to height 0.** *Problem:* styled overlay still invisible. *Cause:* the `landing-page` extension sets `body { position: fixed }`, which breaks `top:0;bottom:0` inset-stretch for fixed children. *Solution:* size fixed full-screen overlays with explicit `100vw`/`100vh`, never inset-stretch.
- **Programmatic checks miss visual bugs.** *Problem:* DOM `isVisible`-style checks passed while the UI was visibly broken. *Cause:* the element existed with a bounding box but rendered invisible (zero height / styling / z-index). *Solution:* verify UI fixes with SCREENSHOTS — Playwright `tools/shot-*.js`, or extract frames from a user recording (`ffmpeg -i rec.mp4 -vf fps=2 f%03d.png`; user recordings are excellent evidence). Playwright against the live packaged app needs NO login (single-user mode, 127.0.0.1 whitelisted).
- **A 15 MB fetch froze the frontend (user-reported: "check your work from the frontend").** *Problem:* the import page fetched `/api/characters/all` on every load — with a large library that's ~15 MB of full cards, which janked/froze the page and even drowned the agent-browser automation. *Cause:* verified API shapes with mocks and tiny fixtures, never with the user's real data volume; `useShallowCharacters` is off, so `/all` returns FULL cards. *Solution:* fetch only when a target world is picked, cache the parsed list in `kv.lwcache` (browser-local kv folder — the storage mirror only syncs `rpg`/`worlds`), render from cache instantly, background-refresh when stale, plus a manual "⟳ Refresh list" button. **Rule: always probe frontend changes with REAL server data (live app), not only mocks — mocks hide data-volume and legacy-shape problems.**
- **Legacy string lorebook wipe.** *Problem:* importing a WI book into a world whose stored lorebook is a legacy plain-text STRING would replace it with []. *Cause:* `raw.lorebook = Array.isArray(raw.lorebook) ? raw.lorebook : []` discards strings. *Solution:* fold a string lorebook into `[{content, type:"world", activation:"always"}]` before appending (`3e466db`).
- **base64 padding breaks name round-trips.** *Problem:* server-saves reconcile skipped every entry and pushed stale values back. *Cause:* names like `...MQ==.json` (padding `=`) failed the client/server name regexes. *Solution:* strip padding in `b64url` everywhere; don't "simplify" it back.
- **Mystery 500s on every kv conflict copy (found 2026-11-18 while verifying imports).** *Problem:* the shim's conflict-copy puts (`<name>.conflict-<ms>.json`) all failed 500 'invalid name' — silent, local writes still worked, so nothing looked broken. *Cause:* the server allowlist regex `[A-Za-z0-9_-]+(\.json|\.tomb\.json)?$` rejects the mid-name dot of the conflict marker the shim itself invented. *Solution:* allowlist `(\.conflict-\d+)?` (`5a5755cf3`). **Lesson: when the client invents a naming convention, check it against the server's allowlist in BOTH directions — write a list, then write a conflict copy, then check both.**
- **Relative dataRoot breaks every kv write (dev server / hub risk).** *Problem:* on `node server.js` with `dataRoot: ./data`, ALL kv puts/deletes failed 'invalid name' — but the packaged Windows app worked. *Cause:* `dataFile`/`tombFile` compared `path.resolve(dir, name).startsWith(dir)` — resolve returns an ABSOLUTE path while `dir` is relative, so the check always failed. The packaged app is immune only because Electron global mode makes dataRoot absolute (`appPaths.data`). *Solution:* resolve the dir once and compare like-for-like (`acc572cac`). Check the hub's config: if its dataRoot is relative, its kv mirror has been rejecting everything.
- **World Editor tabs never switched panes (user recording, 2026-11-18).** *Problem:* after "Add as world", the World Editor's tab strip highlighted Story/Lorebook/Stats/… but the panel kept showing Basics, with fragments of other panes overlapping ("buggy tabs and overlapping text and boxes"). *Cause:* `showTab` toggles the `hidden` attribute on `.ce-view` panes, but the stylesheet's `.ce-view { display: flex }` beats the UA `[hidden]{display:none}` rule — an author `display` always wins over the UA hidden rule. The initial pane never left, new panes collapsed to height 0 and stacked behind it. Same class of bug on `.ce-lore-aiwrap` ("Split text with AI" wrapper could never collapse). The codebase's own convention is explicit `[hidden]` display rules (`.ce-dirty[hidden]`, `#tavernFab[hidden]`, …) — these were simply missing upstream. *Solution:* **[rpge-patch 002]** in `PATCHES.md` — two CSS rules (`.ce-view[hidden]`, `.ce-lore-aiwrap[hidden]` → `display:none`), `8245fc0`/`9bc37ae`. **Rule: when a page toggles `hidden` on an element that has ANY author `display:` rule, add the explicit `.x[hidden] { display: none }` rule — and screenshot EVERY tab/pane of a freshly imported artifact, not just the landing tab (each pane paints independently; one clean tab proves nothing).**
- **Editor diagnostics double as a budget check.** While verifying the fix, the Context tab showed the imported girlfriends world at **9,111 tokens vs the 6,000 Perchance-era budget** (rules + 4 cast entries + recent events) — expected for rules-cards and the reason roadmap item 6 (drop the 6,000 cap under the bridge) matters.
